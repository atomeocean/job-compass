# 15. 3Sum

## Problem in plain words

Given a list of integers, return every distinct triplet of values whose sum is zero. The three values must come from three different positions, but two triplets that hold the same values count as one answer. Output order does not matter in the usual problem.

For example, `[-3, 1, 2, -1, 0, 1, -2]` has four distinct triplets: `[-3, 1, 2]`, `[-2, 0, 2]`, `[-2, 1, 1]` and `[-1, 0, 1]`. The two `1` values may appear together in `[-2, 1, 1]`, because they sit at different positions, but `[-3, 1, 2]` is reported only once although either `1` could complete it.

This implementation returns each triplet in ascending order and the list of triplets in sorted order, so the output is predictable. Lists with fewer than three values return `[]`. The input list is unchanged.

## Key idea

Sort a copy of the input. Fix the smallest value of the triplet, then search the part to its right with two pointers: one at the left end and one at the right end. In a sorted range, a sum that is too small can only grow by moving the left pointer right, and a sum that is too large can only shrink by moving the right pointer left. Skipping equal neighbors removes duplicate triplets without a set.

## Step by step

1. Sort a copy of the input, so the caller's list keeps its order.
2. For each index `first`, stop if its value is positive: three values that are all at least that large cannot sum to zero.
3. Skip `first` if its value equals the previous one; that value was already used as the smallest member.
4. Set `left` to `first + 1` and `right` to the last index.
5. Compute the three-value sum. If it is negative, move `left` right. If it is positive, move `right` left.
6. If it is zero, record the triplet, move both pointers inward, then keep moving `left` past values equal to the one just used and `right` past values equal to the one just used.
7. Continue until the pointers meet, then try the next `first`.

In the example, the sorted copy is `[-3, -2, -1, 0, 1, 1, 2]`. With `-3` fixed, only `1 + 2` closes the gap. With `-2` fixed, the pointers find `0 + 2` and then `1 + 1`. With `-1` fixed, they find `0 + 1`. With `0` fixed, the remaining values are all positive, so no triplet exists.

Why nothing is missed: for a fixed `first`, a pointer moves only when every pair it could still form gives a sum on the same wrong side of zero, so it cannot be part of any remaining answer. Why nothing repeats: each distinct smallest value is fixed once, and after a match both pointers leave the values they just used.

## Complexity

For `n` values, sorting takes **O(n log n)** and the two-pointer scans take **O(n^2)** in total, so time is **O(n^2)**. Auxiliary space is **O(n)** for the sorted copy; sorting in place would reduce it but would change the caller's list. The output itself can hold up to O(n^2) triplets.

## Common mistakes

- Using a set of tuples to remove duplicates hides a pointer bug and costs extra memory.
- Skipping duplicates of `first` by comparing with the next value instead of the previous one drops valid triplets such as `[-1, -1, 2]`.
- Moving only one pointer after a match can record the same triplet again.
- Breaking out when the current value is zero misses `[0, 0, 0]`; break only when it is positive.
- Three nested loops are correct but take O(n^3) time.
