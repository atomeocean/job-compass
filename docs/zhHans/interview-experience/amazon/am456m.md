# Amazon SDE2 四轮面试经验

<InterviewDetail />

## 基本信息

- **岗位**：Software Development Engineer II（SDE2）
- **面试轮数**：4 轮
- **面试内容**：LLD、DSA、System Design、Leadership Principles
- **申请渠道**：海投
- **候选人背景**：硕士，在职跳槽
- **面试结果**：等待结果

## Round 1：LLD

### Playlist Mixing System

设计一个 Playlist 系统，将以下两个来源的歌曲混合：

- DJ Service
- Recommendation Service

要求支持：

- 自定义比例或 1:1 混合
- 根据用户偏好进行过滤
- Production-ready 的 Class / Interface / Method 设计

这一轮要求在纸上直接写完整类结构和代码语法。

### Leadership Principles

- 有没有 push back customer 的经历？
- 有没有为了长期目标牺牲短期目标？

### 表现

整体思路理解了，但代码没有完整写出来，这一轮发挥不理想。

## Round 2：DSA

### Q1：Sweetness Distribution

给定两个数组 `A[]`、`B[]` 和 `M` 个学生，分配 sweetness，并使 total sweetness 最小。

现场只完成了 brute-force solution。

### Q2：Maximum Distance Seat

```text
seats[] = {'O','U','U','U','O','O'};
```

找到距离最近 occupied seat 最远的空位。

答案：

```text
index = 2
```

这一题完成 optimal solution。

### Leadership Principles

- 有没有主动改善过职责范围之外的流程？

## Round 3：DSA

原本以为会考 HLD，但实际是两道 DSA，总时间约 45 分钟。

面试官要求先解释思路、复杂度，再从零写 optimal code。

### Q1：Validate Chessboard

给定只包含两种颜色的二维数组，判断是否为合法 chessboard。

### Q2：Longest Common Subsequence

要求依次讨论和实现：

- Recursion
- Memoization
- Tabulation

### Leadership Principles

- 有没有做过客户自己没意识到需要，但实际上很重要的功能？
- 如何解决复杂问题？会和哪些人确认？

面试官会要求同一个问题提供多个不同实例。

第三轮结束约 20 分钟后，HR 安排了 Final Round。

## Round 4：Senior Engineering Manager

最终轮因为第一次网络问题，从 Day 13 改到 Day 18。

内容包括：

### Leadership Principles

- 和 senior 意见不一致的经历
- 收到 critical feedback 的经历
- 如何验证 AI 工具输出
- 如何发现并修复 AI 生成的错误代码

AI Code Validation 这一题中，面试官进一步追问是否只是手动测试，明显比较关注系统化测试思路。

### System Design

#### YouTube-like Video Storage System

Functional Requirements：

1. Upload video
2. Download video
3. Watch video
4. Search video

设计中覆盖：

- Video Chunking
- S3 / Blob Storage
- Presigned URL
- CDN
- Manifest File
- Video Post-processing
- 多种视频清晰度
- Elasticsearch

最后讨论了系统如何 scale。

面试官整体互动不多，并提前约 10 分钟结束面试，因此比较难判断结果。

## 总结

四轮分别覆盖：

- **Round 1**：LLD + LP
- **Round 2**：DSA + LP
- **Round 3**：DSA + LP
- **Round 4**：System Design + LP

整体比较看重：

- Optimal solution
- Time / Space Complexity
- Production-ready LLD
- Scalability
- 多个 Behavioral 实例

虽然第一轮 LLD 和第二轮 Q1 表现一般，但仍然顺利进入后续轮次和 Final Round，所以单轮失误并不一定直接导致淘汰。

最终结果等待正式反馈。
