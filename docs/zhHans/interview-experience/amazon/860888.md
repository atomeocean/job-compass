# Amazon L5 Software Development Engineer Onsite面试经验

<InterviewDetail />

## 基本信息

- **岗位**：Software Development Engineer（L5）
- **面试形式**：Phone Screen + Virtual Onsite（4轮）
- **申请渠道**：内推
- **候选人背景**：硕士，应届毕业生
- **面试结果**：Fail

## Timeline

- 内推后约两周收到 Recruiter 联系
- Recruiter Call 后约一周进行 Phone Screen
- Phone Screen 通过后一周进行 Virtual Onsite（4轮）
- VO 两天后收到拒信

整体流程推进速度比较快。

## Recruiter Call

Recruiter Call 主要介绍了：

- 岗位情况
- 整个面试流程
- 时间安排
- 是否接受 Relocate

没有涉及任何技术内容。

## Phone Screen

Phone Screen 时长约 45 分钟。

### Coding

算法题为 LeetCode 中等难度题，整体难度不高。

没有特别刁钻的 Follow-up，更注重：

- Communication
- 一边写代码一边解释思路
- 分析 Time Complexity 和 Space Complexity

### Leadership Principles

这一轮主要考察：

- Ownership
- Learn and Be Curious

LP 部分采用标准 STAR 形式，但不会只听完整个故事，而是不断追问细节。

整体发挥不错，顺利进入 VO。

## Virtual Onsite

### Round 1

#### Coding

算法题为 LeetCode Medium。

完成后继续追问：

- 时间复杂度
- 空间复杂度
- 是否存在更优实现

由于做题速度稍慢，时间比较紧张。

#### Leadership Principles

两道 LP，都进行了比较深入的追问，一个故事会持续讨论好几分钟。

### Round 2

#### Coding

依旧是一道经典 LeetCode Medium。

属于二叉树纵向遍历相关题目。

一开始没有想清楚节点 Index 的处理方式，后来在面试官提示下完成。

#### Leadership Principles

主要考察：

- Think Big
- Earn Trust

依然会围绕人与团队协作不断深挖。

### Round 3（Bar Raiser）

这一轮是 System Design。

题目：

**Design Kindle Reader**

需要完成：

- API Design
- Database Schema
- Overall Architecture

随后进行了大量 Follow-up，包括：

- Reader Offline 怎么处理？
- 一个账号多个 Kindle 同时阅读同一本书怎么办？
- Reading Progress 如何同步？
- 如何避免多个设备互相覆盖阅读进度？
- Conflict Resolution 如何设计？
- API 如何保证幂等？
- 如何保证数据一致性？

整个讨论涉及：

- Database Schema
- API Design
- Cache
- 数据同步
- Consistency

回顾整个过程，主要问题在于回答过于关注底层实现细节，例如 API、数据库设计等，而没有持续从以下角度展开讨论：

- Customer Experience
- High-level Design
- Design Trade-off

System Design 更重要的是说明为什么这样设计，以及不同方案之间的取舍，而不仅仅是实现方式。

### Round 4

#### Coding

算法题属于 DFS 类型的经典题。

#### Leadership Principles

主要考察：

- Dive Deep
- Deliver Results

讨论内容更加偏技术实现以及项目影响范围（Scope & Impact）。

## 面试总结

### Coding

Amazon L5 对 Coding 仍然有比较高的要求。

整体以 LeetCode Medium 为主，但希望能够：

- 写出正确代码
- 清晰解释思路
- 分析复杂度
- 回答优化方案

### Leadership Principles

LP 在 Amazon 中的重要性远高于很多其他公司。

建议至少准备 8～10 个 STAR 故事，并且每个故事最好能够覆盖多个 Leadership Principle，因为面试官会持续深入追问各种细节。

### System Design

这次最大的失误在于讨论过程中一直停留在：

- API
- Database
- Implementation Details

而忽略了：

- Customer Obsession
- High-level Architecture
- Trade-off Analysis
- Assumptions

Amazon 的 System Design 更希望看到的是设计思考过程，而不仅仅是技术实现。

## 面试结果反馈

- **最终结果**：Fail
