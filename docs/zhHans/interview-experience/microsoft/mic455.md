## Round 3：Data Structures & Algorithms

这一轮约 1 小时，共三道 Coding 题。

### Q1：Maximum Consecutive Ones with up to K Flips

给定一个二进制数组，最多可以将 `K` 个零翻转为一，求最长连续一的长度。

#### LeetCode 对应

[1004. Max Consecutive Ones III](https://leetcode.com/problems/max-consecutive-ones-iii/)

- **难度**：Medium
- **对应程度**：题意完全一致

#### 解题思路

使用 Sliding Window 和双指针，记录当前窗口内零的数量。

当零的数量超过 `K` 时，移动左指针缩小窗口，并更新满足条件的最大窗口长度。

#### 复杂度

- **Time Complexity**：`O(n)`
- **Extra Space**：`O(1)`

### Q2：Minimum Time to Burn a Binary Tree

给定二叉树中的一个目标节点，火从该节点开始，沿相邻节点传播，求烧完整棵树所需的时间。

#### LeetCode 对应

[2385. Amount of Time for Binary Tree to Be Infected](https://leetcode.com/problems/amount-of-time-for-binary-tree-to-be-infected/)

- **难度**：Medium
- **对应程度**：核心问题相同，LeetCode 使用感染传播的描述

#### 解题思路

先找到目标节点，再从该节点开始进行 BFS。

每个节点可以向以下相邻节点传播：

- Left child
- Right child
- Parent

使用 visited 集合避免重复访问，每一层 BFS 对应一个时间单位。

#### 与 LeetCode 的区别

面试题中的节点结构已经包含 parent pointer。

LeetCode 版本需要自行建立子节点到父节点的对应关系。

#### 复杂度

- **Time Complexity**：`O(n)`
- **Extra Space**：`O(n)`

#### 表现

候选人完成了解答，面试官确认正确，没有要求修改。

### Q3：Message Filtering within a K-second Window

给定 timestamps、messages 和时间窗口 `K`，返回一个布尔向量，表示每条消息应该被接受还是被抑制。

#### LeetCode 对应

[359. Logger Rate Limiter](https://leetcode.com/problems/logger-rate-limiter/)

- **题目访问**：Premium
- **对应程度**：相近题目，并非完全一致

标准题目使用固定的 10 秒窗口；面试版本使用可变窗口 `K`，并要求返回布尔向量。

#### 解题思路

使用 Hash Map，记录每种消息最近一次被接受的 timestamp。

处理新消息时，根据当前 timestamp 与上一次被接受时间的差值，决定是否接受该消息。

#### 需要确认的规则

被抑制的消息是否更新 timestamp，会影响实现方式：

- **按最近一次接受时间限流**：仅在消息被接受时更新时间。候选人采用这一规则。
- **按最近一次出现时间过滤**：每次出现都更新时间，包括被抑制的消息。

因此，应在 Coding 前确认窗口判断依据。

#### 复杂度

- **Expected Time Complexity**：`O(n)`
- **Extra Space**：`O(m)`
- `m` 为不同消息的数量

### 整体表现

候选人在规定时间内较为顺利地完成了全部三道 Coding 题。

## 面试结果与反馈

**最终结果：Rejected。**

正面反馈包括：

- 理论知识扎实
- 推理与表达清晰
- DSA 能力较强

主要顾虑在于实际经验的深度，尤其是较大规模系统的设计经验，没有达到目标职级的预期。

面试方认为候选人具备基础与潜力，但还需要更多真实项目中的系统设计实践。

## 总结

三轮分别覆盖：

- **Round 1**：项目经历 + System Design
- **Round 2**：Attack-path System OOD + 路径验证或构建
- **Round 3**：Sliding Window + Tree BFS + Hash Map

候选人的主要体会是，系统设计准备需要结合过往项目中的具体决策，能够解释：

- 当时的业务需求与技术约束
- 考虑过哪些替代方案
- 为什么选择最终方案
- 做了哪些 trade-offs
- 上线后遇到了什么问题
- 从实践中获得了哪些经验

本次经历中，较好的 Coding 表现与理论基础，仍未能弥补面试方对实际系统设计经验深度的顾虑。
