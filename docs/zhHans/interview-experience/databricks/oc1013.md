## 面试流程概览

本次 Onsite 面试主要包含三部分：

1. Coding - Tic-Tac-Toe
2. Coding - Track Creator Rewards with Sponsors
3. System Design - Chat System

## 第一轮：Coding - Tic-Tac-Toe

第一轮 Coding 要求实现一个可以实际运行的 **Tic-Tac-Toe（井字棋）** 游戏。

### 题目要求

游戏需要支持两名玩家，并在每次有效落子后自动切换玩家。

每次落子之后，需要打印当前棋盘，以展示游戏当前状态。

程序还需要正确处理以下三种游戏结束情况：

- 玩家一获胜
- 玩家二获胜
- 棋盘达到平局

### Follow-up

Follow-up 要求加入一个 **AI 玩家**。

AI 玩家需要能够自动完成自己的落子，同时继续遵循原本的游戏流程和结束条件。

## 第二轮：Coding - Track Creator Rewards with Sponsors

第二轮 Coding 题目是 **Track Creator Rewards with Sponsors**。

题目要求根据 Sponsorship（赞助）关系追踪 Creator 的 Reward。

### Follow-up

Follow-up 在原本要求的基础上增加了新的条件：

除了直接的 Sponsor 关系之外，**间接的 Sponsorship 关系**也需要计入 Reward 的计算。

## 第三轮：System Design - Chat System

第三轮要求设计一个 **Chat System（聊天系统）**。

讨论主要集中在以下三个方面：

- API Design
- Database Schema 和 Data Modeling
- 基础的端到端 Chat Flow

根据原帖描述，这一轮没有花太多时间深入讨论大规模 Capacity 或高级 Scalability 问题。

主要讨论内容集中在：

- 核心 API
- 数据持久化模型
- 消息流程
