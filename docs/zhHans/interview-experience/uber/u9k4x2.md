# Uber Senior+ SDE 面试经验

## 面试基本信息

- 公司信息：[Uber](https://www.uber.com/us/en/careers/)
- 面试时间：2026年9月

## 面试过程

### Technical Screen

第一轮是一道矩阵相关的算法题。

题目给定一个 matrix，需要通过相邻元素交换（adjacent swaps）的方式，将矩阵中的元素重新排列成 snake order。

完成基础实现后，面试官继续追问如何减少交换次数，并要求补充测试用例验证实现。除了能否得到正确结果之外，这一轮也比较关注复杂度、操作次数以及边界情况。

### Onsite Coding

Coding Round 是一道 grid 上的路径查询问题。

系统需要处理多次 shortest-path query，同时路径还存在额外限制，例如经过的数值需要满足递增关系。

相比单纯套用 BFS 或 Dijkstra，这道题更强调如何把路径搜索与额外约束结合，同时考虑多次查询情况下的效率。

### System Design

系统设计题目是设计一个用于存储大型结构化数据集的分布式存储系统。

讨论内容包括：

- 数据如何分布和存储
- Cache 设计
- Queue 的使用
- Failure handling
- Load balancing
- 系统扩展性
- 不同设计方案之间的 trade-off

面试官会根据候选人的方案持续进行 follow-up，因此不仅需要给出总体架构，也需要解释每个组件为什么这样设计。

### Behavioral / Hiring Manager

Behavioral 部分主要围绕过去的项目经验和工作经历展开。

相比单纯的行为问题，这一轮更接近对候选人技术决策、协作方式以及 Senior-level ownership 的综合考察。

### 总结

这套流程比较明显地体现了 Senior+ 岗位对综合能力的要求。

Coding 题并不完全是标准 LeetCode 原题，而是会加入额外约束和 follow-up；System Design 的深度也比较高，需要能够讨论 caching、queue、failure handling 和 distributed architecture。
